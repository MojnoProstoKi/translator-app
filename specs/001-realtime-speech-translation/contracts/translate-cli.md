# Contract: `translate-cli`

CLI-обёртка над `TranslationEngine` (Constitution Principle II: каждая библиотека предоставляет
CLI). Используется для автоматизированного/оффлайн тестирования пайплайна ASR → перевод на
файлах-фикстурах, без запуска GUI-приложения и без живого аудиоисточника.

## Команда

```text
translate-cli --input <path-to-wav> [--format json|text] [--source-lang en] [--target-lang ru]
```

| Аргумент | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `--input <path>` | да | — | Путь к WAV-файлу с англоязычной речью (16-бит PCM, моно) |
| `--format` | нет | `json` | `json` — построчный поток JSON-событий; `text` — человекочитаемый вывод |
| `--source-lang` | нет | `en` | Код исходного языка (BCP 47) |
| `--target-lang` | нет | `ru` | Код целевого языка (BCP 47) |

## Протокол ввода/вывода

- **stdout**: поток результатов, по одному `TranslatedSegmentEvent` (см.
  `translation-engine-api.md`) на строку в режиме `--format json` (JSON Lines); при `--format
  text` — построчно `[HH:MM:SS.mmm] <original> → <translation>` c пометкой `(partial)` для
  промежуточных обновлений и `(final)` для завершённых сегментов.
- **stderr**: ошибки (файл не найден, неподдерживаемый формат аудио, язык недоступен on-device,
  сбой ASR/MT-провайдера).
- **Exit codes**: `0` — успешная обработка всего файла; `1` — ошибка аргументов; `2` — ошибка
  выполнения пайплайна (сбой ASR/MT); `3` — недоступен требуемый on-device языковой пакет.

## Пример JSON-события (режим `--format json`)

```json
{"segmentId":"3F2504E0-4F89-11D3-9A0C-0305E82C3301","sourceType":"microphone","originalText":"Hello there","translatedText":"Привет","isFinal":true,"latencyMs":1820}
```

## Контрактные гарантии

1. Для одного и того же входного WAV-файла повторный запуск `translate-cli` детерминированно
   выдаёт то же множество `segmentId` с `isFinal == true` и семантически эквивалентный текст
   (используется интеграционными тестами `TranslationEngineIntegrationTests` для проверки
   стабильности пайплайна на фикстурах).
2. `translate-cli` не выполняет никаких сетевых вызовов при обработке файла — проверяется тем же
   способом, что и в `translation-engine-api.md` (FR-006/SC-004).
3. Команда завершает работу (`exit 0`) после того, как последний сегмент файла получил финальное
   событие — не зависает в ожидании дальнейшего ввода (в отличие от live-режима GUI-приложения).
