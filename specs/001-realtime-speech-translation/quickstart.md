# Quickstart: Перевод речи собеседника в реальном времени (macOS)

Валидационный сценарий, доказывающий, что фича работает end-to-end. Ссылается на контракты и
модель данных вместо дублирования деталей.

## Prerequisites

- macOS 26 (Tahoe) или новее на Apple Silicon (M1 или новее) — см. research.md §5
- Xcode 17+ со Swift 6 toolchain
- Загруженный on-device языковой пакет Speech/Translation для пары en↔ru (система предложит
  загрузку при первом использовании `SpeechAnalyzer`/`TranslationSession`; на реальном устройстве
  сама загрузка занимает секунды — если кажется, что «зависло» на дольше, проверьте `log show
  --predicate 'process == "RealtimeTranslator"'`, а не считайте это нормальной длительностью)
- Разрешения macOS:
  - **Микрофон** и **распознавание речи** — запрашиваются автоматически системным диалогом при
    первом запуске приложения (обычный flow `AVCaptureDevice.requestAccess`/Speech framework).
  - **System Audio Recording Only** (Core Audio Taps, для источника «системный звук») — ⚠️ **для
    этого разрешения macOS НЕ показывает системный диалог вообще** (подтверждено практически: тап
    создавался десятки раз без единого запроса). Добавляется **только вручную**: Системные
    настройки → Конфиденциальность и безопасность → System Audio Recording Only → «+» → выбрать
    `RealtimeTranslator.app` → включить переключатель. Без этого шага приложение будет молча
    получать полностью нулевой (тишина) аудиопоток без единой ошибки — визуально неотличимо от
    «висит и слушает», см. FR-010.

## Setup

```bash
# Из корня репозитория
cd Packages/TranslationEngine
swift build                       # собирает библиотеку и translate-cli
swift test --filter TranslationEngineTests   # unit + contract тесты (без реальных разрешений)
```

```bash
# Сборка GUI-приложения (App/ — Swift Package, не .xcodeproj, см. plan.md → «Примечание по реализации»)
cd App
swift build
swift test

# Приложению нужна настоящая bundle identity (CFBundleIdentifier), иначе TCC-разрешения либо не
# запрашиваются, либо система молча зануляет захваченный звук — запуск через `swift run`
# недостаточен для System Audio Recording. Упаковать в .app и подписать ad-hoc:
BIN=.build/arm64-apple-macosx/debug/RealtimeTranslator
APP=.build/RealtimeTranslator.app
mkdir -p "$APP/Contents/MacOS"
cp "$BIN" "$APP/Contents/MacOS/RealtimeTranslator"
# Contents/Info.plist должен содержать CFBundleIdentifier=com.translator.RealtimeTranslator,
# NSMicrophoneUsageDescription, NSSpeechRecognitionUsageDescription, LSUIElement=true
codesign --force --sign - "$APP"
open "$APP"
```

## Валидация через CLI (оффлайн, без живого звонка)

Проверяет пайплайн ASR → перевод на фикстуре, независимо от GUI и живого аудио (см.
`contracts/translate-cli.md`).

```bash
cd Packages/TranslationEngine
swift run translate-cli --input Tests/TranslationEngineTests/Fixtures/sample-en-greeting.wav --format text
```

**Ожидаемый результат**:
- В stdout появляются строки перевода, помеченные `(partial)`, до финальной строки `(final)` для
  каждой распознанной фразы — подтверждает FR-004/FR-005.
- Exit code `0`.
- Ни одного исходящего сетевого соединения от процесса за время выполнения (проверить, например,
  через `sudo dtrace` или `Instruments → Network`) — подтверждает FR-006/SC-004.

## Валидация основного сценария (User Story 1, P1) — системный звук

1. Запустить видео (или звонок в Zoom/Teams/Discord) с англоязычной речью.
2. Открыть приложение RealtimeTranslator, выбрать источник «Системный звук».
3. Нажать «Начать перевод» — плавающий оверлей должен появиться поверх окна звонка/видео в
   пределах 5 секунд (SC-005).
4. Как только собеседник начинает говорить, перевод на русском должен появиться в оверлее не
   позднее 3–5 секунд от начала фразы (SC-001) и продолжать обновляться до её завершения.
5. Поставить видео/звонок на паузу (тишина) — новый текст перестаёт добавляться (FR-013).

**Независимая проверка**: успешна, если перевод виден и обновляется без необходимости включать
микрофон, как описано в Independent Test User Story 1 (spec.md).

## Валидация сценария с микрофоном (User Story 2, P2)

1. Выбрать источник «Микрофон».
2. Произнести/воспроизвести рядом с микрофоном тестовую английскую фразу.
3. Убедиться, что перевод появляется так же, как при захвате системного звука.

## Валидация управления сессией и хранения (User Story 3, P3 + FR-012/FR-016/SC-006)

1. При первом запуске приложения должны появиться системные запросы разрешений с понятным
   объяснением (FR-010); отклонить одно из разрешений и убедиться, что приложение внятно
   сообщает о невозможности использовать этот источник.
2. Запустить сессию, остановить её кнопкой «Стоп» — захват и перевод немедленно прекращаются.
3. Открыть список прошлых сессий (FR-016) — только что завершённая сессия должна отображаться
   как отдельная запись со временем начала/окончания.
4. Удалить эту запись — операция должна занимать не более 2 действий в интерфейсе (SC-006), после
   чего соответствующий файл в `~/Library/Application Support/<bundle-id>/Sessions/` должен
   исчезнуть (см. data-model.md → SessionTranscript).
5. Убедиться, что на первом запуске и перед каждым стартом сессии показывается напоминание о
   необходимости уведомить/получить согласие собеседника (FR-015).

## Diagnostics

- Структурированные логи (уровня DEBUG и ниже для содержимого текста, INFO — только метаданные:
  источник, провайдер, задержка) — см. Constitution → Additional Constraints. Смотреть через
  `log show --predicate 'process == "RealtimeTranslator"'` (не через встроенный `log` шелла zsh —
  используйте полный путь `/usr/bin/log`, иначе команда будет перехвачена шеллом).
- Живой индикатор уровня звука (эквалайзер) в оверлее — самый быстрый способ проверить, доходит
  ли вообще звук до приложения, независимо от того, работает ли распознавание/перевод: если
  полоски не двигаются при реальном звуке — проблема в разрешении/захвате, а не в ASR/переводе.
  Счётчик «событий получено» в оверлее аналогично отличает «пайплайн ничего не производит» от
  «производит, но с пустым текстом».
- Если on-device языковой пакет не загружен, `translate-cli` завершится с exit code `3` (см.
  `contracts/translate-cli.md`); GUI-приложение показывает ту же ошибку прямо в оверлее (не
  только в логах) с инструкцией открыть Системные настройки.
- Полностью нулевой, стабильный (не «тихий», а именно 0.0) уровень звука в системном источнике
  почти всегда означает отсутствующее разрешение **System Audio Recording Only** (см.
  Prerequisites выше), а не баг в коде захвата — подтверждено изолированным тестированием тапа
  в отрыве от всего приложения.
